## Running the bots

```bash
# Live trading loop (Bot 1 → 2 → 3 orchestrated)
python main.py

# Backtest only (last 7 days, no live credentials needed)
python bot4_backtest.py

# Run any bot standalone for debugging
python bot1_gainers.py
python bot2_signals.py
```

Stop the live bot cleanly with `Ctrl+C` or `SIGTERM` — it finishes the current scan cycle before exiting (SIGINT/SIGTERM handled in `main.py`).

No build step, linter config, or test suite exists in this repo. Syntax-check before running:
```bash

    python -c "import ast; ast.parse(open('$f').read())" && echo "$f OK"

```


## Architecture

Four-bot pipeline against Binance USDT-M perpetual futures (LONG only, via `ccxt.binanceusdm`).

```
main.py  (orchestrator loop, SCAN_INTERVAL_SECONDS cadence)
  │
  ├─ Bot 1  bot1_gainers.py   – builds watchlist every GAINERS_REFRESH_MINUTES
  │         union of today's rolling 24h + yesterday's daily candle top-N gainers
  │
  ├─ Bot 2  bot2_signals.py   – scans watchlist; holds per-symbol cooldown state
  │         15m (trend) → 3m (filter) → 1m BOUNCE trigger only
  │         record_exit() called by Bot 3 to update cooldown counters
  │
  ├─ Bot 3  bot3_executor.py  – places orders, manages positions
  │         execute_trade(signal) + manage_positions() called each cycle
  │         holds reference to Bot 2 (signal_bot=) for cooldown feedback
  │
  └─ Bot 4  bot4_backtest.py  – standalone historical replay; mirrors Bots 2+3 logic
             outputs charts/ directory: one PDF per symbol, one page per trade
```

`utils.py` — four shared helpers: `get_exchange()`, `fetch_ohlcv_df()` (returns DataFrame with `ema200` pre-computed), `setup_logging()`, and `normalize_symbol()` (converts raw symbol strings like `BTCUSDT` to ccxt USDM format `BTC/USDT:USDT`).

**All tunable parameters live exclusively in `config.py` — never hardcode values elsewhere.**

`test1.txt`, `test2.txt`, `test3.txt` in the repo root are legacy backtest output logs. They contain CROSS-trigger entries because they were generated by a prior version of the code that emitted both BOUNCE and CROSS signals. The current code is **BOUNCE-only** in both live (Bot 2 `check_signal()`) and backtest (Bot 4 `_check_signal_at()`). The CROSS detection code (`crossed_above` field) still exists in `_analyze_tf()` and is available if CROSS support is re-enabled.

## Key design details

### Signal detection (Bot 2 / Bot 4)

- EMA-200 computed fresh each call via `ewm(span=200, adjust=False)` on fetched candles.
- **BOUNCE only**: 1m candle low ≤ EMA200 × (1 + `EMA_TOUCH_BUFFER_PCT`) AND close > EMA200.
- `_analyze_tf()` also computes `crossed_above` (prev close ≤ EMA, current close > EMA), but `check_signal()` currently only emits BOUNCE signals. The CROSS data is available if CROSS support needs to be added.
- Signal is rejected when:
  - Symbol is in cooldown (consecutive losses, session R threshold, or min re-entry gap)
  - 1m EMA slope is flat or negative over `EMA_SLOPE_LOOKBACK` bars (ranging market filter)
  - Prior swing high in lookback is < `MIN_DEVIATION_ATR_MULT × ATR(14)` above EMA (price must have genuinely departed before pulling back)
  - Trigger candle volume < `MIN_TRIGGER_VOLUME_RATIO` × 20-bar average
  - `SKIP_3M_EMA_TOUCH` is True and last completed 3m bar was itself touching its EMA200

### Order lifecycle (Bot 3)

- Entry: MARKET buy → STOP_MARKET (hard SL, `closePosition: True`) → three `TAKE_PROFIT_MARKET` partial-close orders.
- Hard SL: placed at `swing_low × (1 − SL_SWING_LOW_BUFFER)`. Falls back to `EMA × (1 − SL_BUFFER_PCT)` when `swing_low` is 0.
- Trailing SL: `manage_positions()` polls open orders each cycle. TP1 fill → SL trails to entry; TP2 fill → SL trails to TP1 price.
- EMA-close SL: `manage_positions()` force-closes if the EMA-close SL conditions fire (see below).
- Per-symbol state (entry price, TP/SL order IDs, current SL level `'initial'|'entry'|'tp1'`) lives in `ExecutorBot._position_state`.
- When a position disappears, bot3 calls `signal_bot.record_exit(symbol, approx_r)` — R is approximated from the SL level reached: `initial` → -1.0R, `entry` → +0.534R, `tp1` → +1.948R.

### EMA-close SL

**Bot 3 (live)** — `_check_ema_sl()` implements only the basic counter: exit when `consec >= SL_CONSEC_CLOSES` OR `total_in_window >= SL_TOTAL_CLOSES` (window = `SL_CLOSES_WINDOW` bars). Bot 3 does NOT import or use `SL_DUAL_TF_ENABLED`, `SL_VOL_CONFIRM_ENABLED`, or `SL_TIME_STOP_BARS`.

**Bot 4 (backtest)** — `_simulate_trade()` implements four combinable methods:

1. **Counter** (always active): same consec/window logic as Bot 3.
2. **Dual-TF** (`SL_DUAL_TF_ENABLED`): a 1m bar only counts toward the counter when the 3m is also bearish. Filters 1m noise; requires both TFs to confirm weakness.
3. **Volume-confirmed** (`SL_VOL_CONFIRM_ENABLED`): a bar only counts if its volume exceeds `SL_VOL_CONFIRM_RATIO` × 20-bar average. Ignores low-volume chop below EMA.
4. **Time stop** (`SL_TIME_STOP_BARS > 0`): exits at market after N bars with no TP1 hit. Kills stalled trades and frees capital.

Per-bar evaluation priority in `_simulate_trade`: (1) trailing price SL, (2) TP hits + SL trail, (3) EMA-close SL counter, (4) time stop.

**Important**: `SL_DUAL_TF_ENABLED`, `SL_VOL_CONFIRM_ENABLED`, `SL_VOL_CONFIRM_RATIO`, and `SL_TIME_STOP_BARS` only affect backtest results. Changing them has no effect on live trading until Bot 3's `_check_ema_sl` is updated to import and use them.

### Overtrading prevention (Bot 2 / Bot 4)

`SignalBot` maintains `_symbol_state` per symbol:
- **Consecutive loss cooldown**: after `CONSEC_LOSS_COOLDOWN_COUNT` consecutive losses, symbol is paused for `CONSEC_LOSS_COOLDOWN_MINUTES`.
- **Session R threshold**: if a symbol's cumulative R in the current session drops below `SYMBOL_SESSION_R_THRESHOLD`, it is paused for `SYMBOL_SESSION_PAUSE_HOURS`.
- **Min re-entry gap**: `MIN_REENTRY_MINUTES` (live) or `MIN_REENTRY_CANDLES` (backtest) must pass after any exit before re-entering the same symbol.
- **Daily cap**: at most `MAX_TRADES_PER_SYMBOL_PER_DAY` entries per symbol per calendar day.

In the backtest (`_run_symbol`), equivalent state is tracked locally per symbol walk-forward.

### Backtest simulation (Bot 4)

`run()` operates in two phases:

**Phase 1 — Pool fetch**: calls `find_historical_gainers(n=POOL_SIZE)` to get a wider candidate set (default 20), then fetches full 1m data for every symbol in that pool. All data is held in memory for phase 2.

**Phase 2 — Dynamic windows + simulate**: `_compute_window_gainers()` walks the backtest window in `WATCHLIST_REFRESH_HOURS` steps (default 4h) and at each boundary ranks the pool by `GAINERS_LOOKBACK_HOURS` % change (default 24h) using the already-fetched 1m closes — no extra API calls. The resulting `{window_ts: set_of_top_N}` dict is passed to `_run_symbol()`, which skips new entries when the symbol is not in the active set for that bar's 4h window. Active positions are never interrupted mid-trade.

Other simulation invariants:
- Look-ahead prevention: 3m/15m EMAs computed on resampled data then index-shifted forward one bar (`_resample_and_align`), so each 1m bar only sees the last *completed* higher-TF bar. The third return value `at_ema_aligned` detects when that completed bar was itself a BOUNCE/CROSS — used for `SKIP_3M_EMA_TOUCH`.
- Warmup: `WARMUP_DAYS = 3` prepended to each symbol's fetch window so EMA-200 is fully seeded.
- ATR precomputed once per symbol before the walk-forward loop (not recomputed per bar).
- R-multiples use initial `sl_dist = entry - sl_price` as 1R throughout. Trailing SL exits yield fractional R (BE_SL ≈ +0.534R, TP1_SL ≈ +1.948R on remaining fraction).
- `TradeResult.exit_reason` values: `ALL_TPS`, `TP2+EMA_SL`, `TP1_SL`, `TP1+EMA_SL`, `BE_SL`, `EMA_SL`, `TIME_SL`, `SL`, `OPEN`, `SKIP`.

#### Chart output

After each backtest run, `plot_trades()` writes TradingView-style charts to `charts/`:
- One PDF per symbol (e.g. `charts/BTCUSDT.pdf`)
- First page: summary table of all trades for that symbol
- Subsequent pages: one chart per trade showing candlesticks, EMA-200, SL/TP levels, entry/exit markers, risk-reward zones

### Position sizing

- Risk per trade: `RISK_PER_TRADE_PCT` % of free USDT balance ÷ SL distance in price = contract quantity.
- Hard cap: notional ≤ `MAX_POSITION_NOTIONAL_PCT × balance × LEVERAGE`.
- Quantity and price rounded to exchange precision via `decimal_to_precision`.
